🚀 Overview

This is a comprehensive backend API for a Service Provider Platform built with Node.js, Express.js, and MongoDB. The platform connects customers with service providers and includes features like property management, booking system, payment integration, and admin dashboard.

🌐 Base URL & Authentication

Base URL

http://localhost:8000/api/v1

Authentication

The API uses JWT (JSON Web Token) for authentication. Include the token in the Authorization header:

Authorization: Bearer <your-jwt-token>

⚙️ Environment Configuration

🗄️ Database Models

1. Auth Model (Users & Admins)

{
  name: String,
  email: String,
  phone: String,
  password: String,
  role: ["user", "admin"], // default: "user"
  token: String,
  type: String, // default: "active"
  
  // Permission flags
  isVendor: Boolean,
  isBlog: Boolean,
  isUser: Boolean,
  isSupport: Boolean,
  isJob: Boolean,
  isAds: Boolean,
  isBooking: Boolean,
  isEmpManage: Boolean,
  isCategoryManage: Boolean,
  isManageService: Boolean,
  
  timestamps: true
}

2. Vendor Model

{
  // Basic Info
  name: String,
  email: String,
  password: String,
  phone: String,
  company: String,
  address: String,
  description: String,
  
  // Service Details
  typeOfService: String,
  category: ObjectId (ref: Category),
  subCategory: String,
  yearOfEstablishment: String,
  serviceLocation: String,
  alternatePhone: String,
  whatsappNumber: String,
  businessType: ["Proprietorship", "Partnership", "LLP", "Private Limited", "Other"],
  gstNumber: String,
  tradeLicense: String,
  numberOfStaff: Number,
  
  // System Fields
  role: "vendor",
  status: String,
  percentage: String,
  
  // Working Hours
  workingHours: {
    monday: { start: String, end: String, available: Boolean },
    tuesday: { start: String, end: String, available: Boolean },
    // ... for all days
  },
  
  // Bank Details & Documents
  bankDetail: { accountNumber, IFSC, accountHolderName, branch },
  experience: { fields: [String], totalYears: Number },
  profilePhoto: String,
  document1-5: String,
  
  timestamps: true
}

3. Property Model

{
  title: String (required),
  price: String (required),
  location: String (required),
  type: String (required),
  category: String (required),
  description: String,
  status: ["active", "inactive"], // default: "active"
  images: [{ public_id: String, url: String }],
  vendor: ObjectId (ref: Vendor, required),
  review: [ObjectId] (ref: RatingAndReview),
  timestamps: true
}

🔗 API Endpoints

Authentication Routes (/api/v1/auth)

POST /login

Description: User/Admin login

Request Body:

{
  "email": "user@example.com",
  "password": "password123"
}

Response:

{
  "success": true,
  "message": "Login successful",
  "token": "jwt_token_here",
  "user": {
    "id": "user_id",
    "name": "User Name",
    "email": "user@example.com",
    "role": "user"
  }
}

POST /register

Description: User/Admin registration

Request Body:

{
  "name": "John Doe",
  "email": "john@example.com",
  "phone": "1234567890",
  "password": "password123"
}

GET /getAll

Description: Get all users (Admin only)

Response: Array of user objects

PUT /update/:id

Description: Update user permissions

Parameters: id - User ID

DELETE /delete/:id

Description: Delete user account

Parameters: id - User ID

Vendor Routes (/api/v1/vendor)

POST /login

Description: Vendor login

Request Body:

{
  "email": "vendor@example.com",
  "password": "password123"
}

POST /register

Description: Vendor registration

Request Body:

{
  "name": "Vendor Name",
  "email": "vendor@example.com",
  "password": "password123",
  "phone": "1234567890",
  "company": "Company Name",
  "typeOfService": "Service Type",
  "address": "Complete Address"
}

GET /getAll

Description: Get all vendors

PUT /working-hours/:id

Description: Update vendor working hours

Request Body:

{
  "workingHours": {
    "monday": { "start": "09:00", "end": "18:00", "available": true },
    "tuesday": { "start": "09:00", "end": "18:00", "available": true }
  }
}

Property Routes (/api/v1/property)

POST /create

Description: Create new property

Request Body:

{
  "title": "Property Title",
  "price": "50000",
  "location": "City, State",
  "type": "Residential",
  "category": "Apartment",
  "description": "Property description",
  "vendor": "vendor_id"
}

GET /getAll

Description: Get all properties

PUT /update/:id

Description: Update property details

Booking Routes (/api/v1/booking)

POST /create

Description: Create new booking

Request Body:

{
  "vendorId": "vendor_id",
  "customerId": "customer_id",
  "serviceDate": "2024-01-15",
  "serviceTime": "10:00 AM",
  "description": "Service description",
  "amount": 1000
}

GET /getAll

Description: Get all bookings (Admin)

Payment Routes (/api/v1/razorpay)

POST /capturePayment

Description: Create Razorpay order

Request Body:

{
  "amount": 1000,
  "currency": "INR",
  "receipt": "receipt_id"
}

POST /verifyPayment

Description: Verify payment signature

Request Body:

{
  "razorpay_order_id": "order_id",
  "razorpay_payment_id": "payment_id",
  "razorpay_signature": "signature"
}

Category Routes (/api/v1/category)

POST /create

Description: Create new category (Admin)

POST /purchase

Description: Purchase category by vendor

GET /getAll

Description: Get all categories

Additional Routes Available:

  • Blog Routes (/api/v1/blog) - CRUD operations for blog management
  • Contact Routes (/api/v1/contact) - Contact form submissions
  • Customer Support (/api/v1/customer-support) - Support ticket management
  • Job Routes (/api/v1/job) - Job posting and management
  • Career Routes (/api/v1/career) - Career opportunity management
  • Rating & Review (/api/v1/rating) - Service rating system
  • Ads Routes (/api/v1/ads) - Advertisement management
  • Dashboard Routes (/api/v1/dashboard) - Admin dashboard statistics
  • Image Routes (/api/v1/image) - Image upload and management
  • Audit Logs (/api/v1/audit) - System activity logging

🏦 Payment Integration

Razorpay Integration

  • Test Mode: Currently configured for testing
  • Supported Methods: Cards, UPI, Net Banking, Wallets
  • Currency: INR (Indian Rupees)
  • Security: Signature verification for payment confirmation

📁 File Upload

Cloudinary Integration

  • Supported formats: Images (JPG, PNG, GIF, etc.)
  • Storage: Cloudinary cloud storage
  • Security: File type validation and size limits

🗃️ Database Relationships

  • Vendor → Category: Many-to-One relationship
  • Property → Vendor: Many-to-One relationship
  • Booking → Vendor: Many-to-One relationship
  • Booking → Customer: Many-to-One relationship
  • Property → Reviews: One-to-Many relationship

🚀 Deployment Notes

Production Checklist

  • Update environment variables for production
  • Enable Razorpay live mode
  • Configure production MongoDB cluster
  • Set up SSL certificates
  • Configure production email settings
  • Update CORS origins for production domains

Server Requirements

  • Node.js 14+
  • MongoDB 4.4+
  • Minimum 1GB RAM
  • SSL certificate for HTTPS
